# ひらがな あいうえお

3歳児が自分で触って遊べる、ひらがな五十音表のアプリ。
マスをタップすると、その文字ではじまる絵が跳ねて、ことばの音声が鳴ります。

収録は **あ行〜わ行 + 「ん」= 46マス**（五十音ぜんぶ）。

公開先: https://sakanayuki.github.io/cc_hiragana/

## あそびかた

| モード | 内容 |
| --- | --- |
| **あそぶ**（既定） | 表を自由にタップ。絵が跳ねて、ことばが鳴り、画面いっぱいにその文字が出ます。連打しても必ず最新のタップが鳴ります。 |
| **クイズ** | 上に出た大きなひらがなと同じマスを表から探します。5問で1セット。まちがえても減点なし、2回まちがえると正解のマスがそっと光ります。 |

モードの切り替えは、**右上の歯車をタップ**。誤って開いても「とじる」か背景タップですぐ戻れます。
クイズは5問終わったあとの画面で「やめる」を選ぶと、あそぶモードに戻ります。

### 縦持ちはページ送り、横持ちは1画面

並びは五十音表そのままで、**行が列（右から あ→か→さ…）、段が行**です。
縦横で構造は同じで、違うのは1ページに何列出すかだけです。

| 向き | 表示 | ページ |
| --- | --- | --- |
| **縦持ち** | 5列ずつ | 2ページ（あ〜な / は〜わ） |
| **横持ち** | 10列ぜんぶ | 1ページ（ページャは出ません） |

縦持ちの2ページ構成は下記のとおりです。おまけの「ん」は **2ページ目にだけ**置いてあります
（横持ちは1ページなので常に見えます）。

| ページ | 行 | マス |
| --- | --- | --- |
| 1 | あ・か・さ・た・な | 25 |
| 2 | は・ま・や・ら・わ ＋ 「ん」 | 21 |

画面下の大きな矢印でめくり、端まで行くと一周します。実測の1マスの大きさ:

| 端末 | 1マス |
| --- | --- |
| スマホ縦 320x568 | 56〜58px |
| スマホ縦 390x844 | 71px |
| スマホ縦 430x932 | 78px |
| スマホ横 844x390 | 52〜61px |
| スマホ横 932x430 | 59〜68px |
| iPad縦 820x1180 | 150px |
| PC横 1440x900 | 114〜130px |

### 行の色

行の色は **あ→わ で虹をひとまわり**させています。1ページ目（あ〜な）が暖色、
2ページ目（は〜わ）が寒色に分かれるので、いまどちらのページかが一目で分かります。

| あ | か | さ | た | な | は | ま | や | ら | わ | ん |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 赤 | 橙 | 黄 | 黄緑 | 緑 | 青緑 | 水 | 青紫 | 紫 | 桃 | 山吹 |

かな文字（`--ink`）とのコントラストは全行 **6.98〜10.96:1**（WCAG AA の 4.5:1 を上回る）。
おまけの「ん」だけは虹に入れず山吹色のままにして、特別枠だと分かるようにしています。

ページャの矢印やクイズのスピーカーは行の色を使わず、彩度を落とした操作用の色
（`--ui-face` / `--ui-edge`）にしています。行の色を流用すると虹の一色に見えて
表の一部と紛らわしくなるためです。

クイズ中は、出題が変わると**正解の行が載っているページへ自動で送ります**
（1ページに20マス以上あるので、これだけでは答えは割れません）。
2回まちがえてヒントが出るときも同じページへ送るので、光っているマスを見失いません。
横持ちは全部見えているので送る必要がなく、この動きは起きません。

「ん」と「を」はクイズに出しません。音声がそれぞれ「うんち」「えをかく」で、
文字と音の頭がそろわず子どもが混乱するためです。表には出るので、触れば鳴ります。
「ん」はおまけとして、2ページ目（は〜わ）の最下段にだけ置いてあります。

や行（や・ゆ・よ）とわ行（わ・を）は段が欠けています。五十音表として正しい形なので、
表の上でもそのまま空けています。

なお **ふ の音声ファイルだけ訓令式の `hu.mp3`** です（し・ち・つ はヘボン式の
`shi`・`chi`・`tsu`）。データ側のローマ字をファイル名に合わせてあります。

```bash

npm run build      # 型チェック + dist/ 生成

```

### 絵の切り出し

`assets-source/` の4枚（`aka` / `sata` / `nahama` / `yurawa`.jpeg）は、それぞれ
1024x1024 に4x4のマスが並んだスプライトです。番号・タイル背景・枠を取り除いて
背景透過PNGに切り出すのが `tools/slice_sprite.py` です。
**生成物は `public/icons/` にコミット済み**なので、通常は実行不要です。

```bash
python3 -m pip install pillow numpy
npm run slice
```

実行すると `tools/out/contact-sheet.png` も出ます。
46枚すべてで「番号が消えている」「背景が抜けている」「絵が欠けていない」を目視で確認してください。

#### 背景の抜き方

素材にはタイルの丸角枠・その内側の白いリング・左上の番号が入っています。処理は3段階です。

1. **縁飾りを先に切り落とす** — 枠と白いリングは窓の外周0〜12pxに収まっていて、
   絵がその下に潜り込むことはありません。先に内側だけを取り出せば、連結成分を
   たどらずに済みます。
2. **番号を周囲の色で塗り潰す** — 番号は濃紺で必ず左上にあります。青が赤より
   明確に強い暗い画素だけを選んで潰すので、絵の黒い輪郭線は巻き込みません。
   潰した跡は地色になり、次の段階でまとめて落ちます。
3. **地色からの距離で判定する** — 実測したタイル地から一定距離内の画素だけを
   落とします。連結成分を使わないので、ゆびわのように輪郭で囲まれた穴も抜けます。

3 のしきい値が肝で、広げすぎると **やかんの銀・はさみの刃・まくらや紙の白**まで
食べてしまい、狭すぎると地の縁が残ります。タイル地(≈222,228,232)に対して
はさみの刃(171,172,177)は151、やかんの銀(203,207,210)は68、まくらの白(254,254,254)は
89離れているので、44に絞ってあります。素材を差し替えてこれが崩れたら、
`BG_TIGHT` / `BG_LOOSE` を実測し直してください。

## 五十音を増やすには（濁音・拗音など）

1. 新しいスプライトを `assets-source/` に置き、`tools/slice_sprite.py` の `SHEETS` に
   ブロックを1つ追加して `npm run slice`
2. mp3 を `assets-source/audio/` に置き、`public/audio/` へコピー
   （`cp assets-source/audio/*.mp3 public/audio/`）
3. `src/data/characters.ts` の `CHARACTERS` に行を追加し、`KANA_ROWS` に行名を追加
4. 新しい行の色を `base.css` の `--{行}-face` / `--{行}-edge` と
   `board.css` の `.cell[data-row='{行}']` に追加

列数・ページ数は `KANA_ROWS` の数と `Board.rowsPerPage` から決まります。
行を足してページが増えるとページャのドットも自動で増えるので、
CSS の改修は色の追加だけで済みます。縦持ちの1ページあたりの行数を変えたいときは
`ROWS_PER_PAGE_PORTRAIT` を書き換えてください。

## 技術メモ

- **Vite + TypeScript**（フレームワークなし）。ビルド成果物は静的ファイルのみ。
- **音声は Web Audio API**。`<audio>` は再生開始が遅く、連打時に前の音を止められないため使っていません。46ファイルを起動時に一括デコードして持ちます。
- **効果音は `OscillatorNode` で合成**（`src/audio/sfx.ts`）。音声ファイルを増やさずオフラインでも鳴ります。
- **マスの入力は `pointerdown`**。`click` は 100〜300ms 遅れ、3歳児には反応が鈍く感じられます。
- **ただし全画面のシートを出すボタン（右上の歯車）だけは `click`**。タッチでは指を離した位置の要素に click が合成されるため、`pointerdown` で開くと「指の下に出現したばかりの背景」に同じタップの click が当たり、一瞬で開いて閉じます。素早いタップほど再現しやすく、少し長押しすると click の対象が共通祖先に変わるので起きません。overlay を出すボタンは `click` まで待つのが安全です。
- **盤面の構造は縦横で共通**。行が列・段が行の五十音表そのままで、違うのは1ページに出す列数（`--row-count`）だけです。CSS に向き別のグリッド定義はありません。
- **列数は向きだけで決まる**（`Board.rowsPerPage`）。縦持ちは5列で2ページ、横持ちは10列で1ページ。端末サイズを測って段数を変えることはしないので、`ResizeObserver` は不要で挙動も読みやすくなっています。向きの変化は `matchMedia` で拾います。
- **PWA**（`vite-plugin-pwa`）。絵と音を含めて全アセットをプリキャッシュするので完全オフラインで動きます。
- **子ども防御**: ピンチ／ダブルタップ拡大、長押しメニュー、テキスト選択、ドラッグ、2本指スクロールをすべて無効化。外部リンクは 0 個。

## デプロイ

`main` への push で `.github/workflows/deploy.yml` が走り、GitHub Pages に公開されます。

配信方式（Settings → Pages → Source）の切り替えはワークフロー側で行います
（`actions/configure-pages` の `enablement: true`）。手動設定は不要です。
